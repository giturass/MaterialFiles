# 临时打开副本

压缩包内文件的查看、安装先生成本地副本，由 `OpenCacheManager` 和
`OpenCacheStore` 统一管理。每个任务使用
`open_cache/.managed-v1/<UUID>/files/<原文件名>`，避免同名文件相互覆盖。
`last-used` 元数据通过同目录原子替换记录使用时间，不取原文件的修改时间。

## 保留与清理

- 成功交给 Activity 或后台通知的副本保留 **48 小时**，不设容量上限。
- 实际打开、关闭读取句柄或结束内部查看时更新时间；存在活动任务、读取句柄、
  内部查看 Activity 时不回收。最后一次使用结束后再保留 48 小时。
- 复制失败、取消、找不到打开应用、通知被关闭或通知创建失败时，任务退出即
  清理未交付副本。
- 进程中断留下、没有完成标记的目录，下次清理立即回收；完成的副本依照磁盘
  元数据继续计时。损坏的元数据保守保留并记录错误，后续实际访问可修复。
- 应用启动及每次生成副本时异步清理；48 小时是回收资格，不是准点删除的后台
  定时器。应用没有再次运行时，文件可能保留更久。
- 同时检查内部缓存与当前可访问的外部缓存；旧版平铺文件按修改时间判断，旧
  目录使用自身和后代的最新时间。访问旧副本同样刷新保留时间。
- 清理不跟随符号链接；先在锁内将过期目录改名，再在锁外删除，避免删除与
  新读取并发。删除失败留待下一次清理重试。
- 后台“点击打开”通知自动在 48 小时后消失；删除对应副本时也撤销通知。
  通知使用独立任务标签，互不覆盖。

通过 `FileProvider` 返回的本地文件描述符使用关闭回调释放引用；代理描述符
在 `onRelease()` 中释放引用。内部查看器可能直接读取路径，所以 Activity
也持有引用，涵盖等待“另存为”、重新加载和配置变化时的使用。

Android 不提供通用的“外部应用已彻底用完该 URI”通知。关闭一次描述符只代表
一次读取结束，因此仍保留 48 小时宽限。应用进程被杀后只能依赖已落盘的最近
使用时间；系统本身也可能回收缓存，不能承诺副本永久可用。

## 编辑与保存

临时副本向外部应用只授予读取权限，`FileProvider` 同时拒绝写入模式。
“以其他类型打开”遵守同一规则。内部 Sora 编辑器默认只读，显示“临时预览 ·
修改需另存为”；关闭只读后可以编辑缓冲区，但保存和 `Ctrl+S` 都要求选择
缓存之外的位置。

另存为成功后切换到目标文件，后续保存和重新加载使用目标路径，缓存清理不会
删除它。取消选择或保存失败不改变原文档的未保存状态。普通文件仍沿用原来的
保存行为。旧版本已经写入缓存的修改没有单独标记，升级后的旧副本也适用上述
48 小时规则；需要保留的内容应另存。

## 验证

`OpenCacheStoreTest` 使用真实临时目录及可控时钟，覆盖期限边界、无容量限制、
同名隔离、失败/取消/交付失败、重启恢复、多个读者、时间刷新、双缓存目录、
旧目录与符号链接、坏元数据、时钟回拨和读取/删除竞争。

现有 GitHub Actions 的 `:app:testReleaseUnitTest` 会执行这些测试。本机不执行
编译构建。Android 设备上的回归步骤：

1. 打开两个压缩包里的同名文本，检查内容分别正确，临时预览默认只读。
2. 修改后另存到下载目录，再修改并保存、重新加载和旋转屏幕，确认使用的是
   正式文件；取消另存为及保存失败时，修改仍留在编辑器中。
3. 通过“打开方式”和“以其他类型打开”选择外部应用，确认可读取临时副本，
   写入模式被拒绝；普通文件仍可编辑。
4. 后台解压后从通知打开，确认文件可用；测试设备上验证通知期限及清理后通知
   撤销。禁用通知或对应通知渠道后重复后台打开，确认提示重试且副本立即清理。
   打开 APK 和嵌套压缩包也使用相同保留策略。
5. 取消大文件解压及在解压中终止进程，确认没有完成标记的目录会被清理。
