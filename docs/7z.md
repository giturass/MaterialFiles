# 7-Zip 26.04 归档引擎

压缩、浏览和提取使用官方 [7-Zip 26.04](https://github.com/ip7z/7zip/releases/tag/26.04)
（2026-10-05）。2026-10-16 已通过[官方下载页](https://www.7-zip.org/download.html)
及官方 GitHub release 核对为最新稳定版。引擎源码固定到
`9128b80e3a471108678e2b3ec3c985861c8d7b0f`，完整原始源码包随仓库保存，
构建时校验 SHA-256 并解包，不修改其中的压缩、解码或加密实现。

Java/JNI 接口来自 [7-Zip-JBinding 官方仓库的 7z-26.03 分支](https://github.com/borisbrodski/sevenzipjbinding/tree/7486f0dcfc602cd65c0ad7e187bbf0cc005bf6af)，
固定提交为 `7486f0dcfc602cd65c0ad7e187bbf0cc005bf6af`。桥接版本保持上游的
`26.03-2.4`，实际引擎版本为 `26.04`；这是本项目的 Android 源码构建，
不代表上游发布了新的 Android AAR。运行时同时核对两者，防止混入旧共享库。

旧的 `com.github.omicronapps:7-Zip-JBinding-4Android:Release-16.02-2.03` AAR 已移除。
Gradle 编译仓库中的 Java 接口，CMake 从同一份官方源码构建 `lib7-Zip-JBinding.so`
和属性适配 `libarchive_jbinding.so`。支持 ARM64、ARMv7、x86、x86-64，
使用静态 C++ 运行库、16 KiB ELF 页面和 Android 6.0 / API 23。
源码、校验和及 Android JNI 修改见 [来源记录](7zip-jbinding-source.json) 和
[构建说明](../third_party/sevenzip/README.md)。

## 创建格式

| 选项 | 可选内容 | 密码保护 |
| --- | --- | --- |
| 7z | 文件及目录 | AES-256，可加密文件名 |
| ZIP | 文件及目录 | AES-256，密码限 1–99 个可打印 ASCII 字符 |
| TAR | 文件及目录 | 不支持 |
| GZIP、BZIP2、XZ | 单个常规文件 | 不支持 |

六种格式均使用上游正式的格式工厂，包括 `SevenZip.openOutArchiveXz()`。
XZ 使用自己的 Java 条目和 JNI 回调，已删除旧版借用 BZIP2 会话和空 XZ reader
来替换原生句柄的兼容代码。目录、多文件及符号链接不提供 XZ 创建，writer 和文件任务
也会校验限制；默认文件名保留源文件后缀，如 `data.bin.xz`。XZ 支持压缩级别和原始分卷。

创建菜单和 writer 不提供 TAR.GZ、TAR.BZ2、TAR.XZ 组合格式；已有组合归档仍可
浏览和提取。切换格式时同步替换文件名后缀。旧的组合格式偏好回退到 ZIP；原有 XZ
偏好可以恢复。RAR 等没有创建接口的格式不提供创建选项。

“速度优先、标准、质量优先”使用压缩级别 1、5、7。7z/XZ 另显式设置字典为
64 KiB、16 MiB、32 MiB，避免新版 level 7 在 64 位设备上默认使用 128 MiB 字典。
7z 保留固实压缩及默认线程选择；TAR 不显示压缩级别。

官方 handler 每次 `ISetProperties::SetProperties()` 都会重置其他选项。
属性适配一次提交 7z 的 `x`/`0d`/`he`、XZ 的 `x`/`d`，或 ZIP 的 `x`/`em`。
ZIP 密码保护显式选用 `AES256`；配置失败会终止创建。7z 文件名加密在一次创建中完成。
适配直接包含同次构建的官方 `IArchive.h`，使用现代 Unix COM ABI，不再手写旧 p7zip
的虚析构布局。加载属性库后先核对接口版本 `1`，拒绝 JNI 参数及 COM 布局不兼容的旧库。
升级时仍需复核 `OutArchiveImpl` 的句柄和属性约定。

Android JNI 适配在 Java 入口线程预先缓存应用类，并通过全局引用保存会被原生工作线程
使用的 writer 和流接口；查找失败保留 Java 异常并停止创建。同步修复上游
`reportExtractResult` 的 JNI 对象签名，避免新版解压错误回调无法解析。

官方 26.04 的 ZIP writer 仍要求可打印 ASCII 密码，WinZip AES 最多 99 字节；
界面和 writer 均保留校验。7z 支持中文等 Unicode 密码。留空表示不加密。

## 浏览和提取格式

Java 枚举中的 26 种格式均通过自动探测读取：

7z、ARJ、BZIP2、CAB、CHM、CPIO、AR（含 A、LIB、DEB）、FAT、GZIP、
HFS、ISO、LZH、LZMA、NSIS、NTFS、RAR、RAR5、RPM、SPLIT、TAR、
UDF、WIM、XAR、XZ、Z、ZIP。

原生构建另外注册 PPMd、LZMA86、Hxs 和 Ext，共 30 种 handler。
没有 Java 枚举值的格式也可以自动探测；未知后缀、磁盘映像和 NSIS 的 EXE 可通过
“打开方式 → 压缩包”打开。是否支持某种变体和压缩方法取决于实际编译的上游 handler。
新引擎可读取 ZIP Zstandard（方法 93），不增加 Zstandard 创建选项。
GZIP/BZIP2/XZ/LZMA/LZMA86/PPMd/Z 中的 TAR 自动展开为真实目录，普通单文件压缩流
显示其单个文件。XZ 现使用正式枚举识别，继续支持 `.tar.xz` 展开。

普通文件名由 JBinding 解码，不提供无效的“压缩包文件名编码”设置。
新版 TAR 已消费 GNU `L`/`K` 及 PAX `g`/`x`/`X` 扩展头，元数据适配按新索引规则
对齐，并保留全局 PAX 默认值、字段删除、纳秒时间、路径和链接目标。
合法的本地 PAX 大小覆盖由新引擎读取；与非零旧头冲突的大小、未支持的 PAX 稀疏布局
及非 UTF-8 `hdrcharset` 明确报错。普通名为 `@PaxHeader` 的文件仍保留。
TAR 硬链接继续解析到归档内真实条目，拒绝循环、缺失和越界目标。
新版 `reportExtractResult` 报告的压缩块错误会传回原有 I/O/密码错误通路。

## 密码、分卷和文件提供方

- 密码只用于当前归档文件系统的内存状态，不写入日志或持久设置。已记住的密码从新到旧
  尝试；文件名加密在打开时提示，文件内容加密在提取时提示。列表页处理
  `ArchivePath` 对应的密码操作并刷新同一目录；错误密码可再次输入，取消不会重复弹出，
  旋转屏幕不会重复请求，离开原目录后回调不会刷新另一个目录。
- 7z/RAR 固实数据通过单次 `IInArchive.extract()` 批量解码。64 KiB 有界队列将
  native 回调接到文件提供方的流接口，等待每个目标的覆盖/跳过决定；重试与不同任务
  各自拥有 reader。CRC 错误在返回成功的 EOF 前上报。
- 创建分片为 7-Zip 的原始连续分卷：`archive.ext.001`、`.002` 等，
  不是 ZIP 多磁盘记录。支持不分片、5/10/50 MiB 和自定义大小。
  浏览或提取从 `.001` 开始；RAR 多卷由 `IArchiveOpenVolumeCallback` 请求同目录卷。
- 压缩写入需要回写头部。分片或非 Linux 文件提供方先在私有缓存完成归档，再顺序输出，
  兼容 FTP 等无法安全随机写的提供方。内部临时文件直接通过 `RandomAccessFile`
  读写，避免走用户文件提供方、root 策略和媒体扫描。ZIP 创建的源文件需要支持定位，
  不支持时先暂存；其他创建格式顺序读取。读取归档时也会暂存无法定位的压缩输入。
- 目标以 `CREATE_NEW` 创建。错误、取消或目标 close 失败会回滚本任务新建的输出，
  不删除已有文件。“压缩成功后删除源文件”默认关闭，只在归档和全部输出关闭成功后执行；
  删除前再次检查实际归档过的文件，发生变化或新增的内容会保留。
- 归档路径先检查绝对路径、盘符与越界的 `..`，不允许卷回调读取归档目录以外的路径。
  native 保存的回调异常会还原为 I/O 或取消异常。合法的短读写会循环完成，
  源文件变化、截断和无法继续的读写会报错。

Termux 可单独构建全部原生 ABI，输出及日志位于 `~/tmp`：

```sh
python -B tools/build_archive_jbinding.py
python -B tools/verify_sevenzip_native.py
```

第二条命令复用已校验的本机 ABI 引擎对象，链接独立的测试程序；要求预先安装官方
`7zz` 26.04，并与构建命令使用相同的 `--ndk`、`--cxx`。测试直接调用引擎，
不经过 Java 或 JNI 回调。每次运行在 `~/tmp/materialfiles-sevenzip-native-test/`
下新建目录，保存 `report.json`、`commands.json` 和编译、压缩提取日志。
本次 ARM64 原生测试全部通过，独立解码检查覆盖 17 个归档。

完整 Android 构建继续使用项目的 Gradle/CMake 配置（NDK 版本仍由 `app/build.gradle`
指定）。有外部构建的 Debug APK 后，可在受支持环境运行原有套件：

```sh
python -B tools/verify_archives.py \
  --gradle-home /path/to/gradle-cache \
  --android-jar /path/to/android-sdk/platforms/android-37.2/android.jar \
  --java-home /path/to/jdk \
  --apk /path/to/app-debug.apk
```

套件先查询实际 APK JNI 的 26.04 版本、JBinding 26.03-2.4 和属性接口版本 1，再执行创建、读取、
密码、分卷、取消和事务回滚检查。新增 ZIP Zstandard、PAX 大小覆盖、GNU 扩展头及路径
安全样本；旧的固定格式样本继续使用原始提交和校验和，以检查兼容性。
这些新增应用用例尚未执行。历史 16.02 的 APK 测试计数不作为本次升级结果。
