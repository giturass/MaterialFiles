# 7-Zip-JBinding 归档引擎

压缩、浏览和提取统一使用
[7-Zip-JBinding-4Android](https://github.com/omicronapps/7-Zip-JBinding-4Android)
的 `Release-16.02-2.03`，固定提交为
`875f38aac441f41e6eb693177e020e97971dca97`。Gradle 依赖坐标：

```text
com.github.omicronapps:7-Zip-JBinding-4Android:Release-16.02-2.03
```

项目不再包含 libarchive 依赖、旧的 `NativeSevenZip` 绑定或自行维护的 7z C++ 引擎。
上游 AAR 提供 `lib7-Zip-JBinding.so`，包含 ARM64、ARMv7、x86、x86-64 四种 ABI，
ELF 支持 16 KiB 页面。应用的 `libarchive_jbinding.so` 只为同一个引擎设置创建属性，
不包含压缩或加密算法。应用最低版本仍是 Android 6.0 / API 23。

## 创建格式

| 选项 | 可选内容 | 密码保护 |
| --- | --- | --- |
| 7z | 文件及目录 | AES-256，可加密文件名 |
| ZIP | 文件及目录 | AES-256，密码限 1–99 个可打印 ASCII 字符 |
| TAR | 文件及目录 | 不支持 |
| GZIP、BZIP2 | 单个常规文件 | 不支持 |

这五种对应 `ArchiveFormat.isOutArchiveSupported()` 的全部创建接口。
实际使用 `openOutArchive7z()`、`openOutArchiveZip()` 等按格式区分的工厂，
显式设置压缩级别。创建菜单和 writer 已移除 TAR.GZ、TAR.BZ2 组合格式；
已有组合归档仍可浏览和提取。创建对话框默认显示包含完整后缀的文件名，
切换格式时同步替换原格式后缀。已移除格式的旧偏好回退到 ZIP。

该版本没有 XZ、RAR 等格式的 Java 创建接口，因此创建菜单不列出这些格式；
旧的 XZ 创建偏好会回退到 ZIP。XZ 仍可提取。上游 ZIP 引擎支持 `em=AES256`，
应用通过属性适配显式选择它；配置失败会终止创建，不会回退到 ZipCrypto。
固定版本的 `ZipHandlerOut.cpp` 仍要求密码为可打印 ASCII，`WzAes.h` 限制为
99 字节。界面和 writer 均校验长度与字符，密码可包含空格、英文字母、数字及
ASCII 标点（U+0020–U+007E）；7z 支持中文等 Unicode 密码。留空表示不加密。

“速度优先、标准、质量优先”分别使用压缩级别 1、5、7。7z 的质量级别限制为 7，
避免 level 9 对应的更大字典。7z 使用默认固实压缩和线程选择；TAR 不显示压缩级别。

上游存在[多个属性相互重置的问题](https://github.com/omicronapps/7-Zip-JBinding-4Android/issues/37)。
`SevenZipArchiveProperties` 通过原生 `ISetProperties` 一次设置 7z 的 `x`/`he`，
或 ZIP 的 `x`/`em`。7z 文件名加密由一次创建完成，不再生成临时归档后更新头部。
适配只读取固定版本 `OutArchiveImpl.sevenZipArchiveInstance` 的 `IOutArchive` 句柄，
经 `QueryInterface` 获取并释放属性接口；运行时核对引擎和 JBinding 版本，升级依赖时
必须重新核对 ABI 和属性行为。

## 浏览和提取格式

上游 Java 枚举声明的全部 25 种格式均通过自动探测读取：

7z、ARJ、BZIP2、CAB、CHM、CPIO、AR（含 A、LIB、DEB）、FAT、GZIP、
HFS、ISO、LZH、LZMA、NSIS、NTFS、RAR、RAR5、RPM、SPLIT、TAR、
UDF、WIM、XAR、Z、ZIP。

原生构建还注册了 XZ、PPMd、LZMA86、Hxs，共 29 种格式；
这四种没有对应的 Java 枚举值，仍可自动探测读取。
GZIP/BZIP2/XZ/LZMA/LZMA86/PPMd/Z 中的 TAR 会自动展开到真实目录；
普通单文件压缩流显示其单个文件。
压缩文件后缀、MIME 类型和 manifest 打开入口保持一致；未知后缀与 NSIS 的 EXE
可以通过“打开方式 → 压缩包”显式打开。格式是否能处理特定压缩方法、损坏文件或
变种取决于上游库，枚举不等于每种变体都支持。

普通文件名由 JBinding 解码，PAX 扩展字段由 UTF-8 元数据适配处理。
原 libarchive 专用的“压缩包文件名编码”设置已删除，
不会再提供不起作用的设置。文本编辑器的编码功能不受影响。

TAR 的 PAX 路径、链接目标和时间通过元数据适配恢复，元数据和文件内容仍由
JBinding 提取；普通名为 `@PaxHeader` 的文件会保留。该版本原生 TAR 无法正确处理的
PAX 大小覆盖、PAX 稀疏布局和非 UTF-8 `hdrcharset` 会明确报错，避免输出被截断或错名。

## 密码、分卷和文件提供方

- 密码只用于当前归档文件系统的内存状态，不写入日志或持久设置。已记住的密码从新到旧
  尝试；文件名加密在打开时提示，文件内容加密在提取时提示。列表页处理
  `ArchivePath` 对应的密码操作并刷新同一目录；错误密码可再次输入，取消不会重复弹出，
  旋转屏幕不会重复请求，离开原目录后回调不会刷新另一个目录。
- 7z/RAR 固实数据通过单次 `IInArchive.extract()` 批量解码。64 KiB 有界队列将
  native 回调接到文件提供方的流接口，等待每个目标的覆盖/跳过决定；重试与不同任务
  各自拥有 reader。CRC 错误在返回成功的 EOF 前上报。
- 创建分片为 7-Zip 的原始连续分卷：`archive.ext.001`、`.002` 等，
  不是 ZIP 多磁盘记录。支持不分片、5/10/50 MiB 和自定义大小。
  浏览或提取从 `.001` 开始；RAR 多卷由 `IArchiveOpenVolumeCallback` 请求同目录卷。
- 压缩写入需要回写头部。分片或非 Linux 文件提供方先在私有缓存完成归档，再顺序输出，
  兼容 FTP 等无法安全随机写的提供方。内部临时文件直接通过 `RandomAccessFile`
  读写，避免走用户文件提供方、root 策略和媒体扫描。ZIP 创建的源文件需要支持定位，
  不支持时先暂存；其他创建格式顺序读取。读取归档时也会暂存无法定位的压缩输入。
- 目标以 `CREATE_NEW` 创建。错误、取消或目标 close 失败会回滚本任务新建的输出，
  不删除已有文件。“压缩成功后删除源文件”默认关闭，只在归档和全部输出关闭成功后执行；
  删除前再次检查实际归档过的文件，发生变化或新增的内容会保留。
- 归档路径先检查绝对路径、盘符与越界的 `..`，不允许卷回调读取归档目录以外的路径。
  native 保存的回调异常会还原为 I/O 或取消异常。合法的短读写会循环完成，
  源文件变化、截断和无法继续的读写会报错。

## 验证方式

在 Android/Termux 上构建 debug APK，再使用项目测试工具实际加载 APK 中的 DEX 与 JNI：

常规 NDK 构建会通过 CMake 构建属性适配。Termux 本地验证如使用预编译 JNI 目录，
应先构建并打包属性适配，避免漏掉新增的共享库：

```sh
python -B tools/build_archive_jbinding.py
```

```sh
python -B tools/verify_archives.py \
  --gradle-home /path/to/gradle-cache \
  --android-jar /path/to/android-sdk/platforms/android-37.2/android.jar \
  --java-home /path/to/jdk \
  --apk app/build/outputs/apk/debug/app-debug.apk
```

测试文件、固定格式样本、官方 7-Zip 交叉检查和日志存放在 `~/tmp`。
这类检查不安装应用、不操作应用数据，也不替代设备上的界面交互验证。
创建测试直接调用应用的输出事务，再使用实际 APK writer/reader；
源和目标提供方仍是可注入短读写、close 失败等行为的测试替身。
密码测试覆盖首次列目录和列表页密码请求的状态处理，未渲染完整 Activity。
ZIP 互操作同时核对本地头、中央目录的 AES 字段和独立 7-Zip 的 `AES-256` 方法，
不能只凭“必须输入密码”判断加密算法。
