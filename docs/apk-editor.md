# APKEditor 工具

长按选择文件后，底部“更多”按以下顺序排列适用操作，全部位于“APK 签名”和“制作共存版”之前：

1. **APK 反编译**：将资源 XML、Manifest 和 Smali 保存为当前目录的新 ZIP。解压后可直接使用文件管理器的编辑器修改内容。
2. **APK 回编译**：选择包含 `AndroidManifest.xml` 的本地 APKEditor 项目目录，输入输出名并选择签名密钥，生成已验签 APK。
3. **APK 分包合并**：选择一个 APKS/XAPK/APKM 容器或多选同一版本的 base 与 split，合并成单体后签名另存。
4. **APK 资源重构**：调用 APKEditor 修复/整理资源类型名称、条目名称与文件路径，再签名另存。
5. **APK 资源保护**：调用 APKEditor 的目录与文件名混淆，同步更新资源表中的路径引用，保留资源类型、Manifest 与 DEX，使用标准 ZIP 并签名。此配置不启用破坏资源表、ZIP/Manifest 结构或 DEX 保护。
6. **APK 信息**：查看包名、版本、SDK、应用类、入口 Activity、权限、分包信息和资源包信息。容器会逐个列出分包信息。

签名或制作共存版时，分包输入**自动调用上述同一合并服务**；用户不需要先手动生成中间 APK。
已有私有签名密钥、密钥导入、新建密钥、签名方案、对齐、验签和输出恢复机制继续共用。
原文件不被覆盖，失败或取消不发布结果。资源重构和资源保护的签名对话框先读取原 APK
的信息及原签名状态；点击开始后才处理资源、重新签名和验证输出。回编译和分包合并显示
准备后的待签名 APK 信息。

单个输入或分包集合总压缩体积最多 512 MiB，展开总大小最多 1 GiB，每个资源表最多 16 MiB，
合并输入资源表总计最多 32 MiB，分包最多 256 个，项目文件/目录最多 50,000 个、深度最多 32。
只对完整且同包名、同版本、唯一 base、无重复 split、依赖齐全的集合执行合并。
APKS 若同时包含多个设备变体，须先解压并选取同一变体。含 OBB 的 XAPK 明确报错。
私有工作目录用于暂存和执行；最终输出目前需要本地目录。

APKEditor 的反编译是资源 XML 与 Smali，不提供 Java/Kotlin 源代码还原。
合并资源和 DEX、移除 split 标记与签名成功并不证明所有动态特性应用都能正常运行。
共存行为和限制见 [APK 共存](apk-coexistence.md)。

源码和依赖固定在 [third_party/apkeditor](../third_party/apkeditor/README.md)。
本地仅运行静态检查；编译、主机行为测试、release 构建和 lint 由 GitHub Actions 执行。
